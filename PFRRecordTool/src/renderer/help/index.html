Connect Safely

  1. Open Records and enter the portal name and integration credentials.
  2. Leave the Production switch off while testing. The badge should read Sandbox.
  3. Save the connection, then confirm the correct portal appears in the header.

Credentials stay in the running app session and are not shown on the AutoPay page.

View or Change a Single Record

Choose Customers, Invoices, or Payments; enter one ID; then select View or Change Record. If several IDs are pasted, this action opens only the first ID.

Review the JSON before saving. Invoice updates include the invoice ID automatically; leaving an invoice status as Outstanding keeps it unchanged when only the balance is edited.

Load Customer Lists

Use one source at a time: a pasted ID list, a CSV file, or Fetch All Customers from Portal. Loading from a new source replaces the current feed and labels where the data came from.

Search works against the complete loaded list even when only part of a very large list is rendered.

Run and Continue Bulk Deletions

  1. Choose regular customer deletion or enable Delete Full Account.
  2. Review the confirmation, which names the active deletion type and number of records.
  3. Watch deleted, failed, and remaining counts in the progress area.
  4. Pause to preserve the remaining queue, continue it later in the same app session, or retry failed records after the cycle.

Find and Select AutoPay Customers

Open AutoPay, set report filters, and fetch customers. Customer ID, name, and email use exact portal matches so they reduce the report before it loads. The AutoPay Status filter can show all customers, only customers with a valid schedule, or only customers without one.

Select All Matching Results includes matches beyond the rows currently rendered. Always check the selected count beside the bulk action before continuing.

Manage an Individual Contract

Choose a customer row to load their current contract. You can create one when none exists, update the loaded contract, or remove AutoPay. The app rechecks the portal immediately before saving or removing to avoid acting on stale information.

Contracts process at midnight in the portal's displayed time zone. The schedule preview shows that time zone when the portal makes it available.

Run a Bulk AutoPay Action

Select customers, then choose an existing portal template, a JSON configuration, or an Excel workbook. Review the next payment date, optional payment method, and selected count before applying.

Customers already on AutoPay are skipped during apply; customers without a contract are skipped during removal. Processing is bounded to protect app and portal performance, and failed temporary requests can be retried.

Use Workbooks and Customer Exports

Download the blank workbook from the AutoPay action panel. Templates holds reusable configurations; Assignments maps customer IDs to templates and optional overrides. Use the AutoPay Workbook topic for every supported column and value.

Export Selected Customers creates a workbook of the loaded customer data and attempts to include the contract wallet first, then the customer's default payment method.

Troubleshooting

No customers load
Confirm the connection, environment, and portal name, then try a broader filter.
A contract action is skipped
The portal state changed or the requested state already exists. Reload the customer before trying again.
No wallet GUID appears
The customer may have neither a contract payment method nor a default payment method, or the lookup may have failed.
The portal time zone is unavailable
Contract changes can still run, but verify the configured portal time zone before relying on the schedule preview.

AutoPay Workbook Reference

Use Templates for reusable settings. Use Assignments to connect customers to a template or provide customer-specific overrides.

Templates One reusable AutoPay configuration per row.
Assignments One customer per row. TemplateName and override columns are optional.
